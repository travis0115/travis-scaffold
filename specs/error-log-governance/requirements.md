# 错误日志治理需求

## 范围

将现有“每次异常一条流水”的错误日志升级为可聚合、可查看发生明细、可处理和可删除的轻量异常治理功能。错误日志仅记录非预期异常，严重级别固定为 ERROR，因此不新增严重级别字段。

## 用户故事

- 运维人员希望在列表中看到同类异常的发生次数、处理状态、模块、平台、用户和最近发生时间。
- 运维人员希望查看完整异常上下文、最近发生明细和可复制的异常堆栈。
- 运维人员希望将异常标记为已解决或已忽略，并记录处理人、时间和备注。
- 有删除权限的运维人员希望删除无须保留的错误日志及其发生明细。

## 验收标准

1. 当同一异常指纹再次上报时，系统应增加发生次数、更新时间和最新上下文，而不是新增另一条聚合记录。
2. 当已解决异常再次发生时，系统应将其恢复为待处理；已忽略异常再次发生时应保持已忽略。
3. 当异常上报时，系统应保留一条独立发生明细，并记录请求、用户、平台、异常和环境快照。
4. 当管理员查询列表时，系统应返回处理状态、发生次数、模块、平台、用户名、请求信息、异常信息和首次/最后发生时间。
5. 当管理员查看详情时，系统应返回聚合信息、最新上下文、最近发生明细、处理信息和可保持换行的异常堆栈。
6. 当管理员提交处理结果时，系统应仅接受已解决或已忽略，并自动记录当前管理员和处理时间。
7. 当管理员删除错误日志时，系统应同时删除所属发生明细，并分别校验处理和删除权限。
8. 当错误上下文包含请求参数时，系统应继续使用既有脱敏快照，不新增原始请求体采集。

## 非目标

- 不采集 WARN、INFO 等普通日志。
- 不增加严重级别配置。
- 不实现任务分派、评论流、通知或外部工单同步。
- 不记录 SQL 语句和 SQL 参数。
