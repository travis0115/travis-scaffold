# 错误日志治理设计

## 数据模型

- `sys_error_log`：异常聚合主记录，唯一键为 SHA-256 异常指纹；保存统计、状态、处理信息和最新异常快照。
- `sys_error_log_occurrence`：每次发生的不可变快照，通过 `error_log_id` 归属主记录；主记录删除时由数据库级联删除。

异常指纹由来源类型、来源名称、异常类型和首个栈帧组成，不包含可能携带动态业务值的异常消息。

## 聚合规则

- 首次发生：创建待处理主记录和发生明细。
- 重复发生：原子增加次数，更新最后发生时间与最新快照，再新增发生明细。
- 已解决后复发：恢复为待处理并清空当前处理结果。
- 已忽略后复发：保持已忽略。

## 模块和平台

- 模块名称从受控的来源类名推导；无法推导时回退为来源类型。
- Web 请求按 `/api/admin/`、`/api/app/` 识别为 `ADMIN`、`APP`；其他来源为 `SYSTEM`。
- 用户名从登录会话写入 MDC，并随异常事件保存为发生时快照，避免 APP 用户与后台用户 ID 重合时串人；旧的后台记录可在查询阶段通过 `SysUserApi` 批量补充。

## API 与权限

- 查询分页和详情：`ops:error-log:query`
- 处理：`ops:error-log:handle`
- 单条删除：`ops:error-log:delete`

处理状态为 `PENDING / RESOLVED / IGNORED`。处理请求必须包含非空备注。

## UI

列表聚合展示来源信息、请求信息和异常信息；长文本省略并提供提示。详情采用宽弹窗分区展示，堆栈使用可滚动的 `pre` 并支持复制。处理使用表单弹窗，删除使用居中确认。

## 验证

- 单元测试覆盖指纹稳定性、聚合写入、复发状态、处理和查询筛选。
- Controller 请求校验覆盖非法状态和空备注。
- 前端运行 travis-admin 类型检查。
- 后端运行 ops 模块聚焦测试与 Spotless 检查。
